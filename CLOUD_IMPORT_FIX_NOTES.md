# JUAN VPN cloud import/UI fix notes

## Changes
- Removed the manual Cloud server URL field and Test server controls from Android Settings.
- Cloud upload/import now use the configured JUAN VPN Worker endpoint internally: `https://juanvpn.juanvpn.workers.dev`.
- Worker exceptions now create a non-secret incident ID and log the operational error, HTTP method, and route in Cloudflare Worker logs. Request bodies, cloud keys, lookup tokens, and configuration contents are not logged.
- Worker API routes fail with a logged diagnostic if the D1 `DB` binding is missing.
- Updated cloud-server documentation and root page text.

## Important: a source change does not prove the live Worker is healthy
The `Server error` shown by the app is generated by the Worker catch-all. The actual cause must be checked in Cloudflare:
1. Open Workers & Pages -> `juanvpn` -> Logs / Tail.
2. Retry one cloud upload/import.
3. Find the matching `JUAN cloud request failed` log and its `incident` value.
4. Confirm the Worker has D1 binding variable `DB` pointing to the existing database ID in `wrangler.toml`.
5. Confirm `schema.sql` has been applied to that existing D1 database. Do not create a replacement database, drop tables, or delete rows.
6. Deploy the updated `cloud-server/worker.js`.

The app-side UI/default endpoint changes require a new Android build and installation. The Worker change must be deployed separately. Do not announce cloud import fixed until a real upload and a real import both succeed.
